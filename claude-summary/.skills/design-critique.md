# Design Critique

Run after implementation is functional and technically coherent.

## Review against

1. locked blueprint;
2. `DESIGN.md`;
3. component identity contracts;
4. actual rendered page at required viewport classes.

## Judge

- hierarchy and first-view clarity;
- composition and controlled asymmetry;
- surface rhythm;
- typography hierarchy;
- CTA priority;
- image purpose and crop;
- premium restraint vs decorative noise;
- cardification;
- repetition between adjacent sections;
- page-specific identity without breaking global identity;
- conversion clarity;
- multilingual visual resilience.

## Output

Only meaningful findings:

- P1 — damages hierarchy, trust, conversion, or locked design identity
- P2 — visible weakness worth correcting
- P3 — optional polish

Do not redesign during critique. Recommend a correction or route to `design-polish`.
