# High-Value Visual Execution

## Authority

Derive visual decisions from the locked blueprint, `DESIGN.md`, active semantic tokens, and reviewed component contracts. This skill adds no palette, spacing scale, radius scale, type scale, or page formula.

## Evaluation

The rendered result must establish one primary hierarchy, clear section purpose, differentiated component identity, controlled whitespace, structural imagery, restrained accents, obvious CTA priority, and calm factual operational information.

Reject repeated equal cards, identical section templates, excessive pills, gratuitous borders, decorative labels without meaning, or effects used to simulate quality.

## Procedure

1. Confirm blueprint completeness before judging polish.
2. Compare each section with its approved identity contract.
3. Diagnose hierarchy using semantic type, measure, spacing, surface, image footprint, and action priority.
4. Make the smallest token-aligned correction.
5. Recheck adjacent sections and every responsive state.

Refinement preserves approved composition, copy, facts, and CTA roles. Replacement is redesign and needs explicit authority.

## Exit

Run design review and the applicable `verify:ui` profile. Subjective polish is not proof of technical or accessibility compliance.
