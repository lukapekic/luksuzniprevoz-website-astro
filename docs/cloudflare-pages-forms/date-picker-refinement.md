# Form date picker refinement — 2026-09-26

## Owner-approved behavior

- Airport start, Booking departure and Booking return use the same schedule controls.
- The visible input remains DD/MM/YYYY. Digits are masked as they are entered: `01092026` becomes `01/09/2026`. Paste, clearing, middle edits and deletion at slashes remain supported. An impossible date is rejected, not corrected to another day.
- A trailing calendar icon opens the browser's native calendar through a feature-detected `showPicker()`. Manual input remains available when unsupported or when opening throws. The native input has no submission name and is excluded from the keyboard tab order. Selected dates update the visible field, canonical payload, summary and saved draft.
- Native picker `input` events are contained until its `change` event is consumed, avoiding restoration of the previous typed value.
- Allowed dates are today through the next calendar-year anniversary, inclusive, in Europe/Belgrade. A February 29 anniversary clamps to February 28. The owner-approved horizon is stored in `src/data/booking.ts`.
- The existing minimum notice still applies to the requested departure instant. Return instants must follow departure, and the return picker minimum follows the departure date. Both journeys must fit the one-year horizon.
- The same range applies to server validation and incoming Airport queries. Expired recovered drafts are preserved for correction but cannot pass validation.

The example `01/09/2026` still formats correctly; if entered after that date, it is rejected as past.
