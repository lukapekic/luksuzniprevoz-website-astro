# Repository Documentation

This directory contains **operational and governance reference documentation** for the Luxury Transportation Astro repository.

It does not define the page design or replace the repository's primary authorities.

## Authority hierarchy

Use the two authority chains from `AGENTS.md`. Technical/foundation decisions start
with root `AGENTS.md` and validated configuration. Visible design decisions use:

1. locked page blueprint;
2. `DESIGN.md`;
3. the active theme and generated semantic tokens;
4. reviewed shared-component contracts;
5. wireframe geometry.

`.skills/` and this `docs/` directory are procedures and operational references;
they never override either authority chain.

A root doc must never override a locked blueprint, `DESIGN.md`, the active theme, or `AGENTS.md`.

## Root docs vs site docs

- `docs/` — repository operations and governance.
- `site/luksuzni-prevoz/src/docs/` — production page/component blueprints, wireframes, and structural contracts.

Do not move page design rules into root operational docs.

## Generated documentation

`rule-traceability.md` is generated by:

```bash
pnpm traceability
```

Validate it with:

```bash
pnpm traceability --check
```

Do not edit it manually.

## Design/theme changes

The production site's active theme is selected **only** by:

```text
site/luksuzni-prevoz/foundation.config.ts
→ activeThemeVersion
```

Shared foundation code must not provide an active-theme fallback. A missing or invalid configured theme is an error.

After a theme-system change, follow the Theme Ownership and Upgrade Protocol in `AGENTS.md` and run the applicable theme and design-governance gates.

Blueprints and wireframes should remain theme-independent by referencing semantic tokens rather than literal colors, spacing, radii, or breakpoints.

## UI/design agent workflow

For production UI work, follow `AGENTS.md` and `.skills/design-governance.md`.

Minimum workflow:

```bash
pnpm design:context --target <exact-file> --surface <surface-id>
# implement
pnpm verify:ui --target <exact-file> --surface <surface-id> --change <profile>
```

For completion-sensitive work, use the stricter repository gate when available:

```bash
pnpm design:guard
```

Harness-specific hooks are fast feedback only; the repository commands remain the canonical enforcement layer.
